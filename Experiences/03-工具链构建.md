# 03 - 工具链构建

## 1. 核心方案：P/Invoke 离线调用 DLL

**不逆向算法，直接调用 QQ 音乐自带的 DLL** 是最高效可靠的解密方式。
原理：`QQMusicCommon.dll` 的 `EncAndDesMediaFile` 类 Open→Read 时会自动解密，
Read 返回的就是解密后的明文。

### 1.1 调用序列（对应 Frida 脚本，已验证）

```
alloc(0x28)                          ; 对象内存
??0EncAndDesMediaFile@@QAE@XZ(obj)   ; 构造
?Open@..._N1@Z(obj, path, 1, 0)      ; 打开（b1=dealDecrypt=1）
?GetSize@...KXZ(obj)                 ; 解密后大小
?Read@...KPAEK_J@Z(obj, buf, size, 0) ; 读取（已解密）
??1EncAndDesMediaFile@@QAE@XZ(obj)   ; 析构
```

### 1.2 C# thiscall 委托

```csharp
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate IntPtr Ctor(IntPtr self);
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate IntPtr Open(IntPtr self, IntPtr filename, byte b1, byte b2);
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate uint GetSize(IntPtr self);
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate uint Read(IntPtr self, IntPtr buf, uint size, long offset);
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate void Dtor(IntPtr self);

// 获取导出
IntPtr p = GetProcAddress(h, "??0EncAndDesMediaFile@@QAE@XZ");
Ctor ctor = (Ctor)Marshal.GetDelegateForFunctionPointer(p, typeof(Ctor));
```

**注意**：C++ 类方法用 `thiscall`，`this` 指针是第一个参数（通过 ECX 传递），
C# 用 `CallingConvention.ThisCall` + 首参 IntPtr 正确映射。

## 2. 关键坑：32 位环境

- `QQMusicCommon.dll` 是 **x86 (0x14c)**，只能在 32 位进程加载
- 64 位 Python / 64 位 csc 均无法加载 → 必须 32 位运行时
- 本机方案：`C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe`
  （**32 位** csc，注意不是 Framework64）

```powershell
C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe /nologo /platform:x86 /out:QqmDec.exe QqmDec.cs
```

## 3. 关键坑：DLL 搜索顺序

### 现象
- 从 exe 所在目录加载 QQMusicCommon.dll（完整路径）→ Open 内部 `LoadLibraryW("CommonFunction.dll")` 失败
- 从 QQ 音乐目录加载（裸名 + SetDllDirectory）→ 成功

### 根因
`Open` 内部用**裸名** `LoadLibraryW("CommonFunction.dll")`，Windows 搜索顺序：
exe 目录 → 系统目录 → PATH → SetDllDirectory 设置的目录。
**SetDllDirectory 必须在加载 QQMusicCommon.dll 之前调用**，且 QQMusicCommon.dll
要用裸名加载（走 SetDllDirectory 路径），Open 内部的裸名 LoadLibrary 才能命中
CommonFunction.dll。

### 正确做法
```csharp
SetDllDirectory(@"E:\QQMusic");        // 必须先调用
IntPtr h = LoadLibrary("QQMusicCommon.dll");  // 裸名
```
> 错误做法：`LoadLibrary(@"E:\QQMusic\QQMusicCommon.dll")`（完整路径）
> 会让其依赖 DLL 从 exe 目录解析，导致 CommonFunction.dll 找不到。

### 备选
把 `CommonFunction.dll` + 运行时 DLL 复制到 exe 同目录也能工作，
但裸名 + SetDllDirectory 更干净。

## 4. 其他坑

| 坑 | 说明 |
|----|------|
| `CallingConvention.ThisCall` 需 .NET 4.0+ | 32 位 csc v4.0.30319 可用 |
| Open 返回 IntPtr 判断 | 返回值实际是 bool（byte），用 `!= IntPtr.Zero` 判断 |
| GetSize 返回 uint | 4GB 以内文件安全 |
| Read 的 offset 参数 | 传 `(long)0` |
| 依赖 DLL | MSVCP140.dll、VCRUNTIME140.dll、ucrtbase.dll、concrt140.dll、CommonFunction.dll 必须在 QQ 音乐目录 |

## 5. 诊断工具写法

Open 失败时读对象字段判断失败点：

| 偏移 | 含义 | 期望值 |
|------|------|--------|
| `[obj+4]` | 文件句柄 | != 0 |
| `[obj+0x10]` | EncType | 2 |
| `[obj+0x14]` | 解密器对象 | != 0 |
| `[obj+0x18]` | CommonFunction 模块句柄 | != 0 |
| `[obj+0x1c]` | keylen + 4 | > 0 |
| `[obj+0x20..24]` | 64 位文件大小 | = 解密后大小 |

```csharp
Console.WriteLine("[0x14]=" + Marshal.ReadInt32(obj, 0x14).ToString("X8"));
```
