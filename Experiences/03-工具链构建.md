# 03 - 工具链构建

## 1. 核心方案：直接调用 QQ 音乐 DLL（两种实现）

**不逆向算法，直接调用 QQ 音乐自带的 DLL** 是最高效可靠的解密方式。
原理：`QQMusicCommon.dll` 的 `EncAndDesMediaFile` 类 Open→Read 时会自动解密，
Read 返回的就是解密后的明文。

### 1.1 调用序列（两种实现通用，已验证）

```
alloc(0x28)                          ; 对象内存
??0EncAndDesMediaFile@@QAE@XZ(obj)   ; 构造
?Open@..._N1@Z(obj, path, 1, 0)      ; 打开（b1=dealDecrypt=1）
?GetSize@...KXZ(obj)                 ; 解密后大小
?Read@...KPAEK_J@Z(obj, buf, size, 0) ; 读取（已解密）
??1EncAndDesMediaFile@@QAE@XZ(obj)   ; 析构
```

### 1.2 实现 A：原生 C（推荐，最终采用）

```c
/* MinGW gcc 32 位下用 __thiscall 直接映射 MSVC thiscall */
typedef void  (__thiscall *FnCtor)(void *self);
typedef int   (__thiscall *FnOpen)(void *self, const wchar_t *path, char b1, char b2);
typedef unsigned int (__thiscall *FnGetSize)(void *self);
typedef unsigned int (__thiscall *FnRead)(void *self, unsigned char *buf, unsigned int size, long long offset);
typedef void  (__thiscall *FnDtor)(void *self);

g_ctor   = (FnCtor)GetProcAddress(h, "??0EncAndDesMediaFile@@QAE@XZ");
g_open   = (FnOpen)GetProcAddress(h, "?Open@EncAndDesMediaFile@@QAE_NPB_W_N1@Z");
g_getSize= (FnGetSize)GetProcAddress(h, "?GetSize@EncAndDesMediaFile@@QAEKXZ");
g_read   = (FnRead)GetProcAddress(h, "?Read@EncAndDesMediaFile@@QAEKPAEK_J@Z");
g_dtor   = (FnDtor)GetProcAddress(h, "??1EncAndDesMediaFile@@QAE@XZ");
```

**关键**：MinGW gcc 的 `__thiscall` 属性让编译器自动把 `this` 放进 ECX，
与 MSVC 的 thiscall 约定完全一致。**无需手写汇编 thunk**。

编译（msys2 mingw32，32 位）：
```bash
gcc -O2 -o QqmDec.exe QqmDec.c -lkernel32 -luser32
```

产物仅 259KB，只依赖系统 DLL（KERNEL32、msvcrt），可独立分发。

### 1.3 实现 B：C# thiscall 委托（备选）

```csharp
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate IntPtr Ctor(IntPtr self);
[UnmanagedFunctionPointer(CallingConvention.ThisCall)]
delegate IntPtr Open(IntPtr self, IntPtr filename, byte b1, byte b2);
// ...

IntPtr p = GetProcAddress(h, "??0EncAndDesMediaFile@@QAE@XZ");
Ctor ctor = (Ctor)Marshal.GetDelegateForFunctionPointer(p, typeof(Ctor));
```

**注意**：C++ 类方法用 `thiscall`，C# 用 `CallingConvention.ThisCall` +
首参 IntPtr 正确映射（需 .NET 4.0+）。

## 2. 工具链选择（踩坑记录）

| 方案 | 结果 | 原因 |
|------|------|------|
| 64 位 Python ctypes | ❌ | DLL 是 x86，无法加载 |
| 64 位 csc（Framework64） | ❌ | 编译产物是 64 位 |
| 32 位 csc（Framework） | ✅ 但慢 | C# 版单文件 7s |
| scoop tcc 0.9.27 (-m32) | ❌ | 无 naked、汇编 `@` 符号崩溃、缺 SetDllDirectoryA |
| scoop mingw-nuwen | ❌ | 只有 x86_64，`-m32` 缺 32 位库 |
| **msys2 mingw32 (i686 gcc)** | ✅ 推荐 | 原生 32 位，支持 `__thiscall` |

### 2.1 msys2 安装要点

```powershell
scoop install msys2
# 首次运行 bash 做初始化
D:\Scoop\apps\msys2\current\usr\bin\bash.exe -lc "echo ok"
# 初始化 pacman 密钥（必须，否则签名错误）
D:\Scoop\apps\msys2\current\usr\bin\bash.exe -lc "pacman-key --init && pacman-key --populate msys2"
# 安装 i686 工具链
D:\Scoop\apps\msys2\current\usr\bin\bash.exe -lc "pacman -Sy --noconfirm mingw-w64-i686-gcc mingw-w64-i686-binutils"
```

**编译时必须把 mingw32/bin 加入 PATH**，否则 cc1.exe 找不到它的依赖 DLL：
```powershell
$env:PATH = "D:\Scoop\apps\msys2\current\mingw32\bin;D:\Scoop\apps\msys2\current\usr\bin;$env:PATH"
gcc -O2 -o QqmDec.exe QqmDec.c -lkernel32 -luser32
```

### 2.2 为什么不用 tcc（详细）

- `__declspec(naked)` 报 "cannot use local functions"
- 汇编 thunk 里符号含 `@`（`_ctor_t@4`）tcc 汇编器直接崩溃
- 内联汇编调用函数指针 + 可变栈参数不可行
- kernel32 导入库缺 `SetDllDirectoryA`（较新 API）

### 2.3 为什么不用 C#

- .NET Framework 4 CLR 冷启动约 0.9s（空程序）
- 单文件解密总耗时 7s（含 DLL 卸载清理）
- 需要 csc + 运行时，分发体积大

## 3. 关键坑：DLL 搜索顺序

### 现象
- 从 exe 所在目录加载 QQMusicCommon.dll（完整路径）→ Open 内部 `LoadLibraryW("CommonFunction.dll")` 失败
- 从 QQ 音乐目录加载（裸名 + SetDllDirectory）→ 成功

### 根因
`Open` 内部用**裸名** `LoadLibraryW("CommonFunction.dll")`，Windows 搜索顺序：
exe 目录 → 系统目录 → PATH → SetDllDirectory 设置的目录。
**SetDllDirectory 必须在加载 QQMusicCommon.dll 之前调用**，且 QQMusicCommon.dll
要用裸名加载（走 SetDllDirectory 路径），Open 内部的裸名 LoadLibrary 才能命中
CommonFunction.dll。

### 正确做法（C 实现）
```c
typedef BOOL (WINAPI *FnSetDllDir)(LPCSTR);
HMODULE hK = LoadLibraryA("kernel32.dll");              /* tcc/部分环境缺此 API */
FnSetDllDir setDllDir = (FnSetDllDir)GetProcAddress(hK, "SetDllDirectoryA");
if (setDllDir) setDllDir(qqDir);                        /* 必须先调用 */
HMODULE h = LoadLibraryA("QQMusicCommon.dll");          /* 裸名！ */
```
> 错误做法：`LoadLibrary("E:\\QQMusic\\QQMusicCommon.dll")`（完整路径）
> 会让其依赖 DLL 从 exe 目录解析，导致 Open 内部裸名加载 CommonFunction.dll 失败。

### 备选
把 `CommonFunction.dll` 复制到 exe 同目录也能工作（裸名搜索先命中 exe 目录）。
注意：C 版 exe 只依赖系统 DLL，tools 目录只需额外放一个 `CommonFunction.dll`。

## 4. 其他坑

| 坑 | 说明 |
|----|------|
| `Open` 返回 bool | 用 `!= 0` 判断（返回值 0/1） |
| `GetSize` 返回 uint | 4GB 以内文件安全 |
| `Read` 的 offset 参数 | 传 `0` |
| 对象内存 | `calloc(0x28)` 全零后传给构造（构造会自己初始化字段） |
| 依赖 DLL | MSVCP140.dll、VCRUNTIME140.dll 等由 SetDllDirectory 指向 QQ 音乐目录解析 |

## 5. 诊断工具写法

Open 失败时读对象字段判断失败点：

| 偏移 | 含义 | 期望值 |
|------|------|--------|
| `[obj+4]` | 文件句柄 | != 0 |
| `[obj+0x10]` | EncType | 2 |
| `[obj+0x14]` | 解密器对象 | != 0 |
| `[obj+0x18]` | CommonFunction 模块句柄 | != 0 |
| `[obj+0x1c]` | keylen + 4 | > 0 |
| `[obj+0x20..24]` | 64 位文件大小 | = 解密后大小 |

```c
/* C 版直接读对象内存 */
unsigned char* obj = ...;
printf("[0x14]=0x%08X\n", *(unsigned int*)(obj+0x14));
```

## 6. 性能定位方法论（重要）

### 现象
单文件解密要 5-7 秒，看似很慢。

### 定位过程（分段计时）
在原生 C 里用 `QueryPerformanceCounter` 对每阶段计时：

| 阶段 | 耗时 |
|------|------|
| LoadLibrary QQMusicCommon.dll | 11 ms |
| Open（初始化解密器+读密钥） | 31 ms |
| Read（实际解密 68MB） | 520 ms |
| WriteFile | 43 ms |
| **解密合计** | **≈ 0.6 s** |

### 结论
剩余 ~5 秒在**进程退出时 DLL 的清理**：Open 创建解密器后，QQMusicCommon.dll
卸载要清理内部资源（实测：只 LoadLibrary 不 Open → 退出 24ms；Open 后退出 → 5s）。
这是腾讯 DLL 固有开销，**换语言无法消除**。

### 优化手段
1. **批量模式**：一次启动处理多个文件，固定开销只付一次
   （2 个文件 6.3s，仅比 1 个文件 5.7s 多 0.6s）
2. 单文件场景建议把多个 mflac 放同一目录一次解
3. 用原生 C 替代 C#：单文件 7s → 5.7s（省 CLR 启动 + JIT）
