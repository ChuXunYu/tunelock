### CreateDecryption 的 key 解析（0x1C30）

```
0x1740 : base64 解码 (查 rdata 的 base64 表, 遇非法字符提前停止)
0x1C30 流程:
  1) strstr(key, "QQMusic EncV2,Key:")
  2) 命中 → EncV2 分支 (0x2690 用两套 28 字节固定表 + 0x4C20 双次解码)
  3) 未命中 → 普通分支 (0x1E38)
  4) keybuf[0:8] = 解码key[0:8]; keybuf[8:] 由 0x4C20 处理（对二进制输入基本不生效→0）
  5) 对象: [0]=keybuf指针 [8]=keylen(=2*解码长度+8)
```

> **修正（2026-08-10 实测）**：`CreateDecryption` 应传入 **eKey 的 base64 原文**（字符串），
> DLL 内部自己 base64 解码 → TEA 派生 → 构建解密器。**不要**传派生的二进制 key。
>
> 历史结论"不直接调 DLL"是错的——那是把"派生 key 再 base64 编码"喂给它（DLL 期望的
> 是数据库里那条 eKey 原文，二次 base64 导致解码错位）。正确用法：
> ```python
> ctx = dll.CreateDecryption(ekey_bytes, len(ekey_bytes))  # ekey = 数据库 EncryptionKey 原文
> dll.Decrypt(ctx, 0, buf, len(audio))
> ```
> 实测：142 个 kgg（key 512 与 256 字节两种）全部用此法解出 FLAC，0 失败。

### Decrypt 主逻辑（0x36D0）

```
keylen = ctx[8]
if keylen <= 300:   // Map 路径
    for i in 0..len: data[i] ^= keystream(ctx, index+i)
else:               // RC4 路径 (0x3350 分段, 0x3780 每段)
    ...
keystream(off) (0x3790):
    if off > 0x7FFF: off %= 0x7FFF
    idx = (off*off + 71214) % keylen
    v   = keybuf[idx]
    r   = ((idx & 7) + 4) % 8
    return ((v << r) | (v >> r)) & 0xFF     // 8 位循环右移 r 位
```

### tan 随机数（0x2020，对应 `simple_make_key`）

```
输出[i] = (byte)(sin(i*0.1 + seed) & mask * 100)   // 实测为 tan: |tan(seed+i*0.1)|*100
```
酷狗 eKey 派生用 seed=106 (0x6A)，生成 8 字节盐。

## 数据库：`KGMusicV3.db` AES 分页加密

```
master_key[24] = 1D 61 31 45 B2 47 BF 7F 3D 18 96 72 14 4F E4 BF 00 00 00 00 73 41 6C 54
page_key(pg)   = md5(master_key[0..16] + pg_le32)
iv_seed(s)     = (s*0x9EF4 - (s/0xCE26)*0x7FFFFF07) mod 2^32 (溢出修正 +0x7FFFFF07)
page_iv(pg)    = md5(由 iv_seed 链式生成 4 个 u32_le)     // 从 seed=pg+1 开始
页1: 特殊 —— 校验 o14==0x20204000 等, 先置换字节再 AES 解密, 最后写回 "SQLite format 3\0"
页N(≥2): AES-128-CBC 解密 (key=page_key, iv=page_iv)
```

解密后为普通 SQLite，歌曲密钥在表：

```sql
SELECT EncryptionKeyId, EncryptionKey FROM ShareFileItems
WHERE EncryptionKey IS NOT NULL AND EncryptionKey != ''
-- EncryptionKeyId = KGG 文件的 audio_hash(0x48 处 32 hex)
-- EncryptionKey   = eKey (base64 文本, ~700 字符)
```

## eKey → 原始密钥派生

```
raw = base64_decode(eKey)
if raw 以 "QQMusic EncV2,Key:" 开头:
    raw = TEA_dec(k1, raw)             // k1 = 16 字节固定表
    raw = TEA_dec(k2, raw)             // k2 = 16 字节固定表
    raw = base64_decode(raw)
# v1 (腾讯 TEA):
sk = [int(|tan(106+i*0.1)|*100)&0xFF for i in 0..8]
tea_key[2i]=sk[i], tea_key[2i+1]=raw[i]
dec = tencent_tea_cbc_decrypt(raw[8:], tea_key)   // CBC 模式 + 2字节salt + 7字节zero
final_key = raw[:8] + dec               // 实测 512 字节
```

腾讯 TEA 变体要点：
- 16 轮标准 TEA，大端 u32，`delta=0x9E3779B9`
- CBC 链式：首块直接解密，后续块 `dest ^= 当前密文块` 后再解密，输出 `dest ^ 上一明文块`
- 输出长度 `= len - 1 - pad - 2(salt) - 7(zero)`

## 解密算法（RC4 / Map）

```
if len(final_key) > 300:  RC4Cipher
else:                     MapCipher

MapCipher.mask(off):
    if off > 0x7FFF: off %= 0x7FFF
    idx = (off*off + 71214) % size
    return ror8(key[idx], ((idx&7)+4)%8)

RC4Cipher:
    KSA: bx[i]=(i&0xFF); j=(j+bx[i]+key[i%n])%n; swap
    hash: 从 key 前若干非零字节连乘, 溢出(0或<=)即停
    seg_skip(id): seed=key[id%n]; (hash/denom)*100 % n   (denom=(id+1)*seed)
    段: FIRST=128, SEG=5120
    enc_first: buf[i] ^= key[seg_skip(off+i)]
    enc_seg  : PRGA (skip 预跳 seg_skip(off/SEG) 后逐字节)
```

数据区从 `audio_offset(0x400)` 开始，`decrypt(audio, 0)` 从头解密。

## kgma / kgm（crypto_ver 3）算法 —— 2026-08-10 破解

> 旧版格式，**密钥内嵌文件头**，无需数据库 eKey（所以数据库查不到是正常的，此前误判为不可解）。

### 文件头结构（KGM magic 相同）

```
0x00  magic  KGM_MAGIC(16)          // 与 kgg 相同
0x10  AudioOffset u32               // 样本 0x400
0x14  CryptoVersion u32             // = 3 (kgma), 4/5 为 kgg
0x18  CryptoSlot    u32             // kgma 样本 = 1
0x1C  CryptoTestData 16B            // = 解密 key 的 16 字节(直接作为 key 使用)
0x2C  CryptoKey     16B             // (kgma 样本此字段未用)
0x400 音频数据开始
```

> `kgma` 实际使用 0x1C 处的 16 字节作为密钥；0x2C 的 CryptoKey 字段不参与 kgma 解密
> （KGG v5 通过数据库 audio_hash 查 eKey，与此不同）。

### 流解密算法（与 kgg 完全不同）

```
key[17] = 文件[0x1C : 0x1C+16] + 0x00        // 第 17 字节补 0

对音频流从 pos=0 起逐字节:
  med8 = key[pos % 17] ^ buf[pos]
  med8 ^= (med8 & 15) << 4
  msk8 = 0
  off  = pos >> 4
  while off >= 0x11:
      msk8 ^= table1[off % 272]; off >>= 4
      msk8 ^= table2[off % 272]; off >>= 4
  msk8 = MaskV2PreDef[pos % 272] ^ msk8
  msk8 ^= (msk8 & 15) << 4
  buf[pos] = med8 ^ msk8
```

- 三张常量表：`table1[272]`、`table2[272]`、`MaskV2PreDef[272]`（见 `scripts/kgm_dec.c` 内嵌数组）
- `med8/msk8` 的 `(x & 15) << 4` 变换在 C 的 uint8 下自动截断，Python 需 `& 0xFF`
- 输出为标准 FLAC/MP3（`fLaC` / `ID3` 识别），样本全部解出 FLAC
- 无 seek 表，`pos` 从 0 连续

### 来源与交叉验证

- 算法移植自开源 `AudioDecrypt`（`MusicDecryptor/Private/KGM.cpp`，KGMBase::getKey 读 0x1C 16 字节，decrypt 用 table1/table2/MaskV2PreDef）
- 已用 167 个 kgma 实测：167/167 解出 FLAC，ffprobe 验证 44100Hz/2ch 正常
- 工具：`scripts/kgm_dec.c`（C 版，秒级批量解密）
